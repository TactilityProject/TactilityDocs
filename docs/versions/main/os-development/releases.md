# Releases

Tactility releases consist of firmware for every supported device, TactilitySDKs for app development, and a simulator build. GitHub Actions builds and publishes them.

## Versions

The current version is in `version.txt` (e.g. `0.8.0-dev`). It ends up in:
- the firmware, shown in System Info
- the SDK's folder name (`<version>-<platform>`), which apps refer to with `target.sdk` in their manifest

## Automated builds

The "Build Firmware" workflow (`.github/workflows/build.yml`) runs for pull requests, pushes to `main` and version tags:

1. **SDKs:** builds a TactilitySDK for every ESP32 target (from the `generic-esp32*` devices) and for the simulator (POSIX).
2. **Firmware:** builds the firmware for every device in `Devices/` (the list is generated by `Buildscripts/gh-generate-device-matrix.py`).
3. **Bundle:** on `main` and tags, bundles the build artifacts.
4. **Publish:** uploads the firmware and SDKs to the CDN (`https://cdn.tactilityproject.org`):
   - a push to `main` publishes a **snapshot**
   - a tag that starts with `v` (e.g. `v0.8.0`) publishes a **stable** release

The CDN feeds the [Web Installer](installing-firmware.md), and `tactility.py` downloads the SDKs from it.

"Build Simulator" builds the simulator for Linux and macOS, and "Tests" runs the unit tests.

## Making a release

1. Set the version in `version.txt` (e.g. `0.8.0`).
2. Commit it, and tag the commit with the same version prefixed with `v` (e.g. `v0.8.0`).
3. Push the commit and the tag. The workflow builds and publishes the stable release.
4. Set `version.txt` to the next development version (e.g. `0.9.0-dev`).

## Device metadata

`Buildscripts/CDN/generate-firmware-files.py` creates the CDN's metadata for each device from its [device properties](device-development/device-properties.md): `general.vendor`, `general.name`, `general.incubating`, `cdn.warningMessage` and `cdn.infoMessage`. Incubating devices and messages are shown in the Web Installer.

## Local builds

The `Buildscripts/` folder has scripts to package local builds:

| Script | Purpose |
|---|---|
| `release.sh <device-id>` | Copies the current firmware build (`build/`) into `release/Tactility-<device-id>`, with the flash scripts, and the `.elf` files with debug symbols into `release/Tactility-<device-id>-symbols` |
| `release-sdk-current.py` | Builds the TactilitySDK for the current build (see [Building TactilitySDK locally](app-development/symbols.md?id=building-tactilitysdk-locally)) |
| `release-simulator.sh <build-dir> <target>` | Packages a simulator build with its `Data/` folders |

A firmware release contains `flash.sh` and `flash.ps1` to flash it with esptool, and `merge.sh`/`merge.ps1` to merge the binaries into a single image (see [Installing Firmware](installing-firmware.md)).

Keep the `-symbols` folder of every release you distribute: it's needed to decode crash backtraces from that firmware.
